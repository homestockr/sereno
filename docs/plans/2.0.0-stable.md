# 2.0.0: the first stable console release

Status: plan written 2026-11-15 by the architect, at Robe's request. Ships as `2.0.0`, the first
non-pre-release since v1.3.0, with plugin `0.6.4`. Robe can overrule any decision below.

## The question it answers

"Is the console ready for someone who isn't us?" The rule from 2026-10-04 was "2.0.0 when the
console ships", and all four tabs (Projects, Spend, Pipeline, Sessions) are now in. This release
adds no new features. It finds and fixes what daily use turns up, closes the small known gaps, and
proves that the upgrade from v1.3.0 is safe.

## Findings (code and repo read 2026-11-15)

- **2.0.0 becomes "Latest" on GitHub.** v1.3.0 is the current Latest, so 2.0.0 is the first
  alpha-line build that people who aren't following the alphas will get. The upgrade from v1.3.0
  must be tested on a real install, not assumed.
- **There is no v1.3.x draft release.** The GitHub API lists no drafts. The "v1.3.x draft
  undecided" item in CLAUDE.md is stale, and 2.0.0 carries the v1.3.1 fixes anyway, so close it.
- **The plugin rewrites `created_at` on every spec revision.** `renderSpec`
  (`plugin/bin/lib/spec.js`) stamps `new Date()` every time. `writeSpec` already keeps `after`,
  `hold_before_merge`, `check_hosts` and `review` from the earlier spec (`readSpecMeta`), but not
  `created_at`. Two things depend on it:
  - **Escaped defects:** a fix spec revised after a re-merge counts against the new merge, so
    the card over-counts. This is a known limit from alpha.8.
  - **The `/sereno:next` queue:** `decide` sorts by `created_at`, oldest first, so revising a
    queued spec today moves it to the back of the queue.
- **The plugin version is only shown globally.** `pluginStatus` (`src/wiring.js`) returns the
  newest version across all `installed_plugins.json` records. Those records are per project
  (`projectPath`, matched case-sensitively; see the plugin path case memory). So a project still
  on 0.6.2 looks up to date, even though its gates won't record `reviewer`.
- **Browse checks** shipped in plugin 0.5 and have never been run end to end.
- **The README** still opens as the v1.x widget README and marks every console section
  "(alpha)".

## Decisions (architect, 2026-11-15)

1. **Daily use comes first, with a short, fixed scope.**
   - Use the installed alpha.8 for at least three working days before any code step.
   - Log what turns up under "Found in use" below.
   - Only bugs and confusing UI get fixed in this release. A new feature idea goes in "Later".
2. **Keep `created_at` across spec revisions** (plugin 0.6.4).
   - A revision keeps the earlier spec's `created_at`, the same way `after` and `hold` are kept.
   - Side effect, intended: a revised spec keeps its place in the `/sereno:next` queue.
   - There is no new field. Old specs already rewritten stay as they are; we don't attempt to
     recover them.
3. **Show the plugin version per project, read-only.**
   - Add the version recorded for each project's `projectPath` to the Projects view, matched the
     same way `pluginStatus` already reads the file.
   - Show a quiet note when a project is behind the newest installed version.
   - No amber: nothing here needs Robe to act right now. No button: Sereno observes.
4. **Run one real browse check before the release.** Run it on a throwaway task in a scratch repo
   with a local page. Fix what breaks. If it can't be made to work in this release, say so plainly
   in the plugin README instead of shipping it silently.
5. **Test the upgrade on real installs.** Do it on the packaged installer, not `npm start`.
6. **Drop "(alpha)" only where it's earned.** Spend, Projects, Pipeline and Sessions lose the label.
   Anything daily use shows to be shaky keeps it, with one line saying why.

## Not doing

- Builder cost per merge, and escapes per Builder model. Wait for a few weeks of 0.6.3 gates.
- Dependabot #54. It stays blocked until electron-builder accepts minimatch 11. If that changes
  before the release, take it.
- macOS or Linux builds.
- Code signing changes beyond what the README's policy already says.
- Rewriting old specs' `created_at`.

## Steps

- **S0, daily use (Robe, no code).**
  - Use the installed alpha.8 day to day for at least three working days.
  - Update the plugin with `/plugin marketplace update sereno`, then `/plugin update` in each
    project.
  - Log findings above. The architect turns them into Builder fixes for S4.
- **S1, plugin 0.6.4: keep `created_at`.**
  - `writeSpec` passes the earlier spec's `created_at` to `renderSpec` when one exists and
    parses as a date. Otherwise it uses now.
  - Bump `plugin.json` and `marketplace.json` to 0.6.4, and add a README changelog line.
  - Tests:
    - a revision keeps the date;
    - a first write sets it;
    - a garbled earlier value falls back to now;
    - the `/sereno:next` queue order is unchanged after a revision.
  - In the app, update the plan note in `alpha8-escaped-defects.md`: the over-count only applies
    to specs revised before 0.6.4.
- **S2, plugin version per project.**
  - `wiring.js` gets `pluginVersions()` (read-only), returning `{ projectPath, version }[]`.
    Use the existing caps and `VERSION_DISALLOWED` cleaning, and treat paths as data only.
  - The collector carries the version onto each project in `/api/projects`, through the existing
    cleaning. Match paths the same way the registry does, and test both "desktop" and "Desktop".
  - Projects view: show "Plugin 0.6.2 (0.6.4 installed elsewhere)" in muted text.
  - Tests: parsing, case handling, a missing file, the project shape, the markup, and no stray hex.
    Look at it in a browser on port 8790.
- **S3, browse check end to end.** The architect runs it with Robe; it is not a Builder step.
  - Follow decision 4, and record the outcome in `plugin-0.5-harness.md`.
  - Any fix becomes one Builder run.
- **S4, fixes from S0 and S3.** Bundle them into one Builder run, following the lean rule.
- **S5, docs.**
  - Rewrite the README opening for the console:
    - what Sereno is now;
    - a screenshot of the console;
    - the widget as the "now" view.
  - Drop "(alpha)" per decision 6, and refresh "Known limits".
  - CLAUDE.md:
    - roadmap item 10 says alpha.8 shipped 2026-11-15;
    - add item 11 for 2.0.0;
    - remove the v1.3.x draft line.
- **S6, upgrade check on the packaged build.** Do this after the version bump to `2.0.0`.
  - **Over v1.3.0:** install v1.3.0, wire it, then install 2.0.0 over it. Check that:
    - the settings in `~/.sereno` are kept;
    - the hooks still fire, and `wire` is idempotent;
    - auto-start still works;
    - the widget comes up and the console opens.
  - **Over alpha.8:** the ledger and `session_events` data survive, and no migration errors appear.
  - **Fresh install** on a clean user profile: the first run, the offer to wire, `unwire`
    restoring the settings byte for byte, and the uninstaller.
  - Confirm `node:sqlite` in the packaged build. This is the last open check from Phase 1, step 7.
  - Write each result here as pass or fail.
- **Then:**
  - the red team on the whole branch;
  - release notes from the Scribe, written for v1.3.0 users, not alpha followers;
  - publish as a full release (not a pre-release), marked Latest.

  Ask Robe before the push, the merge, the release, and the plugin marketplace update.

## Exit criteria

- Every "Found in use" item is fixed or moved to "Later", with a reason.
- S6 passes on all three install paths.
- The suite is green, and the red team passes.
